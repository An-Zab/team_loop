# MASTER PLAN: Модернизация цикла `loop_team` в движке Strata

## Контекст для ИИ-разработчика
Ты — Senior Python Developer. Мы дорабатываем локальный агентский движок **Strata** под ОС **Windows**. 
Наша цель — реализовать автономный цикл выполнения задач (`Аналитик -> Исполнитель <-> Изолированный Ревьюер`) с защитой от переполнения контекста через механизм **Handoff** (`handoff.md`).

### Жесткие правила разработки (Constraints):
1. **Никаких тяжелых фреймворков:** НЕ использовать LangChain / LangGraph. Пишем на чистом Python поверх существующей архитектуры Strata и стандартного клиента OpenAI API (или нативного клиента Strata).
2. **Совместимость с Windows:**
   - Всегда использовать `pathlib.Path` для путей.
   - При любом чтении/записи файлов явно указывать `encoding="utf-8"`.
   - В точках входа принудительно переключать консоль в UTF-8: `sys.stdout.reconfigure(encoding='utf-8')`.
   - При вызове `subprocess` для запуска Python-скриптов всегда использовать `sys.executable` (чтобы оставаться в активном `.venv`).
3. **Бережное отношение к RAM:** Локальная модель одна. Никаких вторых инстансов модели в памяти не поднимать. Изоляция ревьюера делается за счет отправки отдельного stateless HTTP-запроса к тому же локальному серверу без передачи массива истории чата.
4. **Пошаговая работа:** Выполняй **ТОЛЬКО ТОТ ШАГ**, который запросил пользователь. Не пиши код следующих шагов заранее.
5. **Одно правило Handoff и ноль ручных переключений:** Порог Handoff не настраивается — он всегда **60 % от `MAX_CONTEXT_TOKENS`**. Имя модели и размер её контекста в `.env` подставляет `start_team.py` из ответа сервера (`GET /v1/models`), поэтому при переходе на вторую модель (другое имя, другое окно) руками править нечего.
6. **Реалистичные сценарии:** Не закладывать обработку кейсов вида «пользователь выключил сервер на прошлой итерации» и «прошлая итерация до конца куда-то что-то записала». Появится реальная проблема — разберёмся по реальным шагам пользователя.

## ШАГ 0 (обязательная точка входа): интерактивный запуск (`start_team.py` + `start_team.bat`)

**Задача:** Снять с человека два ручных действия — переключение настроек под нужную модель и чистку `handoff.md`.

**Требования к реализации:**
1. `start_team.bat` — исполняемый файл: открывает PowerShell, переводит консоль в UTF-8 и запускает `start_team.py`.
2. **Шаг 2 — проверка модели:** `GET {OPENAI_BASE_URL}/models`. Если есть запись со статусом `loaded` — напечатать «Модель загружена», её имя и контекст. Если модели нет — сказать «загрузите модель» и ждать **Y** (повторить шаг 2) или **N** (выход).
3. **Шаг 3 — подстановка значений:** `MODEL_NAME` = `id` загруженной модели, `MAX_CONTEXT_TOKENS` = её `meta.n_ctx`. Значения пишутся в `.env` с сохранением комментариев и в `os.environ`; отдельный порог Handoff не пишется — он вычисляется из контекста.
4. **Шаг 4 — новая или старая задача:** вопрос «Работаем с новой задачей [Y] или продолжаем старую [N]?»
   - **[Y] новая задача** — удалить `handoff.md` и `handoff.bak` (иначе Аналитик подхватит старый план) и дальше работать с чистым контекстом истории;
   - **[N] продолжаем старую** — оставить `handoff.md` и `handoff.bak` нетронутыми.
5. **Шаг 5-6 — промпт и запуск:** при новой задаче спрашивается её формулировка и запускается `run_strata_team.py "<задача>"`; при продолжении старой спрашивается промпт (по умолчанию «Продолжи выполнение задачи») и запускается `run_strata_team.py --resume "<промпт>"`. Код возврата цикла передаётся наружу.

**Критерий готовности Шага 0:** Двойной клик по `start_team.bat` показывает имя и контекст загруженной модели, обновляет `.env`, а ответы `[Y]`/`[N]` корректно удаляют или оставляют файлы состояния и запускают цикл.

2. Вынести в константы (с возможностью переопределения через `.env`):
   - `MAX_CONTEXT_TOKENS: int = 32768` — полный размер контекстного окна локальной модели. **Единственная настройка, зависящая от модели;** её подставляет `start_team.py` из `meta.n_ctx`.
   - `MAX_STEP_ATTEMPTS: int = 3` — максимум попыток исправления одного шага плана.
   - `HANDOFF_FILE = Path("handoff.md")` и `HANDOFF_BACKUP = Path("handoff.bak")`.
3. Правило Handoff задать **одной константой в коде**, а не парой настроек:
   - `HANDOFF_TRIGGER_RATIO: float = 0.60` — доля контекста, при которой срабатывает Handoff;
   - `HANDOFF_TOKEN_LIMIT: int = int(MAX_CONTEXT_TOKENS * HANDOFF_TRIGGER_RATIO)` — производный порог, отдельно в `.env` не настраивается.
4. Написать функцию `extract_used_tokens(api_response, messages_fallback: list) -> int`:
   - Пытается достать `usage.total_tokens` из ответа сервера.
   - Если локальный сервер не вернул `usage`, считает приближенно по массиву `messages_fallback`: сумма длин всех строк контента деленная на `TOKEN_ESTIMATE_DIVISOR` (`len(text) // N`).
5. Написать функцию `is_context_critical(current_tokens: int) -> bool`, возвращающую `True`, если `current_tokens >= HANDOFF_TOKEN_LIMIT`, то есть контекст заполнен на 60 % и больше.
6. Написать функцию `context_fill_percent(current_tokens: int) -> float` — сколько процентов окна занято, для строк лога.

**Критерий готовности Шага 1:** Модуль импортируется без ошибок, при запуске напрямую (`if __name__ == "__main__":`) выводит в консоль текущие лимиты токенов и самопроверку «HANDOFF_TOKEN_LIMIT = 60 % от MAX_CONTEXT_TOKENS [OK]».

## ШАГ 2: Изолированный Ревьюер с объективной проверкой (`isolated_reviewer.py`)

**Задача:** Создать инструмент проверки шага, который не видит историю метаний Исполнителя и опирается на реальную проверку файлов.

**Требования к реализации:**
1. Написать функцию `run_objective_checks(file_paths: list[str]) -> str`:
   - Проверяет, существуют ли указанные файлы на диске.
   -Для каждого `.py` файла запускает проверку синтаксиса через `subprocess.run([sys.executable, "-m", "py_compile", str(path)], capture_output=True, text=True, encoding="utf-8")`.
   - Возвращает текстовый отчет: либо `"Синтаксис всех файлов корректен"`, либо точный `stderr` ошибки компиляции.
2. Написать главную функцию `review_step(step_goal: str, executor_report: str, modified_files: list[str] = None) -> dict`:
   - Сначала вызывает `run_objective_checks(modified_files)`. Если на этапе `py_compile` есть синтаксическая ошибка — **даже не вызывая LLM**, сразу возвращает `{"accepted": False, "feedback": f"Ошибка компиляции Python:\n{error_text}"}`.
   - Если синтаксис чист, формирует **чистый массив из 2 сообщений** (БЕЗ истории основного чата):
     - `system`: *"Ты — строгий, но прагматичный код-ревьюер. Оцени, выполнен ли текущий шаг плана. Не придирайся к стилю, проверяй только работоспособность и соответствие задаче шага. Если всё выполнено — первой строкой напиши строго слово ПРИНЯТО. Если есть баги или шаг не доделан — первой строкой напиши ДОРАБОТАТЬ и перечисли конкретные правки."*
     - `user`: Сборка только из 3 блоков: `Цель текущего шага`, `Отчет/код исполнителя` и `Результат объективной проверки файлов`.
   - Делает запрос к локальной модели с `temperature=0.0`.
   - Парсит первую строку ответа и возвращает словарь: `{"accepted": bool, "feedback": str, "review_tokens": int}`.

**Критерий готовности Шага 2:** Автономный тест функции `review_step` на валидном и заведомо сломанном коде возвращает корректный словарь `{"accepted": True/False, ...}`.

## ШАГ 3: Менеджер Handoff (`handoff_manager.py`)

**Задача:** Реализовать сохранение состояния при нехватке контекста и восстановление работы в новом чате.

**Требования к реализации:**
1. Функция `generate_handoff(task: str, plan: list[str], current_step_idx: int, recent_messages: list, blocker_reason: str)`:
   - Формирует промпт к локальной модели для сжатия контекста.
   - Требует от модели вернуть ответ **строго по Markdown-шаблону из 4 разделов**:
     1. `# Исходная задача` (текст задачи без потерь).
     2. `# Статус плана` (список всех шагов: выполненные помечены `[x]`, текущий и оставшиеся — `[ ]`).
     3. `# Артефакты и файлы на диске` (какие файлы созданы/изменены и что в них находится, без копирования сотен строк кода).
     4. `# Текущий контекст и блокер` (на каком шаге остановились, последние замечания ревьюера или причина остановки, что нужно сделать первым делом).
   - Записывает результат в `handoff.md` (`encoding="utf-8"`).
2. Функция `load_handoff_if_exists() -> str | None`:
   - Проверяет наличие `handoff.md`.
   - Если файл есть — читает его содержимое, переименовывает `handoff.md` в `handoff.bak` (перезаписывая старый `.bak`, если он был, через `Path.replace`), и возвращает текст.
   - Если файла нет — возвращает `None`.

**Критерий готовности Шага 3:** При тестовом вызове создается читаемый `handoff.md` на русском языке в UTF-8, а при вызове загрузки он корректно переименовывается в `handoff.bak`.

## ШАГ 5: Модернизация главного цикла `loop_team`

**Задача:** Собрать единый пайплайн на базе движка Strata, соединив Шаги 1–4.

**Требования к реализации:**
1. Изучить текущую реализацию `loop_team` и вызова агента/инструментов в Strata.
2. Реализовать обновленный цикл по следующему алгоритму:
   - **Старт:** Вызов `build_execution_plan(task)`. Если был загружен `handoff`, добавить его краткую сводку в системный/начальный контекст Исполнителя.
   - **Внешний цикл (по шагам плана):** `for step_idx, step_text in enumerate(plan):`
     - `attempts = 0`, `feedback = ""`
     - Запоминаем длину истории чата перед началом шага (`history_checkpoint = len(messages)`).
     - **Внутренний цикл (выполнение и ревью шага):** `while attempts < MAX_STEP_ATTEMPTS:`
       1. **Проверка контекста ПЕРЕД вызовом (страховка):** если `is_context_critical(current_tokens)` равно `True` -> вызываем `generate_handoff(...)`, выводим уведомление в консоль и штатно завершаем работу.
       2. **Вызов Исполнителя (Strata Agent):** Передаем ему `step_text` (и `feedback` от ревьюера, если `attempts > 0`). Исполнитель использует стандартные тулзы Strata для чтения/записи файлов.
       3. Обновляем `current_tokens` через `extract_used_tokens(...)`.
       4. **Вызов Изолированного Ревьюера:** Передаем `step_text`, ответ Исполнителя и список затронутых файлов в `review_step(...)`. Ревьюер — отдельный stateless-запрос, основной чат он НЕ увеличивает, поэтому вызывается всегда, даже когда контекст уже на пороге.
       5. **Оценка вердикта:**
          - Если `accepted == True`:
            - *Очистка памяти (Context Pruning):* Если `attempts > 0` (были неудачные попытки), удаляем из истории основного чата промежуточные ошибочные сообщения этого шага (все между `history_checkpoint` и финальным успешным ответом), чтобы не засорять контекст для следующих шагов.
          - Если `accepted == False`:
            - `attempts += 1`
            - `feedback = review_result["feedback"]`
       6. **ОБЯЗАТЕЛЬНЫЙ HANDOFF по завершении работы роли (главное правило):** сразу после вердикта, если `is_context_critical(current_tokens)` равно `True` (контекст заполнен на **60 % и больше**), цикл обязан обновить `handoff.md` и штатно остановиться — работа продолжается **в чистом чате**.
          - Проверка ставится **после** вердикта и **после** Context Pruning, а не сразу после ответа Исполнителя: иначе шаг, уже сделанный и принятый, не попадал бы в `handoff.md` как выполненный и новый чат перерабатывал бы его заново.
          - Для принятого шага в `generate_handoff(...)` передаётся номер следующего шага, то есть принятый помечен `[x]`, а `stopped_at_step` указывает на следующий.
          - Та же проверка выполняется и после незакрытой попытки: шаг остаётся `[ ]`, и именно его продолжаем в чистом чате.
     - **Аварийный выход по попыткам:** Если цикл `while` завершился и шаг не принят (`attempts >= MAX_STEP_ATTEMPTS`), вызываем `generate_handoff(...)` с описанием блокера и останавливаем выполнение.

**Критерий готовности Шага 5:** Цикл проходит многошаговую задачу от начала до конца, переключая шаги после `ПРИНЯТО` и возвращая шаг на доработку при `ДОРАБОТАТЬ`. При заполнении 60 % контекста цикл останавливается ровно на границе шага, а `handoff.md` содержит принятые шаги помеченными `[x]`.

## ШАГ 6: Точка входа и режим стресс-теста (`run_strata_team.py`)

**Задача:** Сделать удобный скрипт запуска из консоли Windows с возможностью проверить Handoff за 1 минуту.

**Требования к реализации:**
1. Настроить `argparse` для запуска из терминала:
   - `python run_strata_team.py "Текст задачи"` — обычный запуск.
   - `python run_strata_team.py --resume` — продолжение работы напрямую из `handoff.md` (даже без ввода текста задачи).
   - `python run_strata_team.py --resume "Продолжи выполнение задачи"` — то же самое плюс уточнение человека; **текст рядом с `--resume` не является ошибкой параметров** и доходит до Аналитика.
   - `python run_strata_team.py "Текст задачи" --test-handoff` — тестовый режим, который искусственно занижает `HANDOFF_TOKEN_LIMIT`, чтобы гарантированно проверить срабатывание генерации `handoff.md` после первого же шага.
2. Добавить понятное логирование в консоль (какой шаг выполняется, номер попытки, сколько токенов использовано из лимита `[Used: X / Limit: Y]` и сколько это процентов окна, вердикт ревьюера).
3. В баннере печатать `MAX_CONTEXT_TOKENS`, действующий `HANDOFF_TOKEN_LIMIT` и долю (60 %), чтобы человек видел правило чистого чата до первого запроса к модели.

**Критерий готовности Шага 6:** Запуск с флагом `--test-handoff` создает `handoff.md` после 1-го шага и останавливается, а последующий запуск с флагом `--resume` подхватывает `handoff.md` и завершает задачу.
